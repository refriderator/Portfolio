Jarvis

October 18, 2026 · Web

https://github.com/refriderator/Jarvis

Jarvis is a Mac assistant I built that lives in the notch. You click the notch (or hit Option-Space) and talk or type to it, and it answers out loud with a caption underneath. It can set timers, check my calendar and Notion, open apps, and hold windows out of the way for me.

I didn’t want yet another chat window. Every new MacBook has that black cut-out at the top of the screen doing nothing, so it seemed like the obvious place to put it.

The dock

This is the part I’m proudest of. If you drag a window by its title bar to the side of the screen, it slides off and leaves a thin sliver behind. Hover over that edge and cards for everything you’ve stashed there pop out. Click one and the window comes back, then tucks itself away again once you move off it. You can also drop a window on the notch and it’ll sit in there instead.

There’s a toy version below you can play with. On a phone, tap the edge instead of hovering. It’s not the real app, but it behaves pretty much the same way.

Some physics that snuck in

All the animations are damped springs, the same x″ + 2ζωx′ + ω²x = 0 from first-year mechanics. Tuning them mostly came down to picking ζ, the damping ratio. An underdamped spring overshoots by e−ζπ/√(1−ζ²), which meant I could choose the numbers on purpose instead of nudging them until they looked okay. When the notch jumps to another display I used ζ ≈ 0.5, which overshoots by about 16% and gives it a bit of bounce. Opening the notch uses ζ ≈ 0.82, so it only overshoots about 1% and just glides open.

Catching windows at the edge needed some hysteresis. A window gets caught once the pointer is within 12 pt of the edge, but it isn’t let go until you pull it 70 pt away. With a single cutoff, a slightly shaky hand sitting right on the line makes the window flicker between caught and not caught. Two thresholds fix that. It’s the same trick as a Schmitt trigger, or the B–H loop of a magnet if you’ve seen that one.

The last one was a stutter that took me a while to track down. To know where other apps’ windows are, Jarvis has to ask macOS, and each of those asks waits on that app to answer. I was checking 30 times a second with the default 6 s timeout, so one busy app could hold things up for hundreds of frames, when each frame only gets 16.7 ms at 60 fps. Checking twice a second with a 0.5 s timeout turned out to be plenty, and the stutter went away.

How it’s built

It’s written in Swift (SwiftUI and AppKit) as a plain Swift package, currently about 17,000 lines across 176 files. I tried to keep each file to one job and under roughly 300 lines, and all the logic sits in its own library so I can test it without launching the app.

When you ask it something, it tries the cheapest thing that can handle it first:

  • plain code for fixed commands like timers and reminders, which is instant and free
  • Apple’s on-device model for summarizing whatever’s already on screen
  • a small local model I trained myself for tool jobs (more on that in the next post)
  • Claude or ChatGPT for anything that actually needs knowledge or good writing

The choice between them is made in code, not by a model. Letting a model decide would add a whole extra call before every answer. In practice most questions never leave the Mac.
